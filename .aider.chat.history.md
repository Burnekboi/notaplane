#### Implementation Plan - Phaser 3 Migration  
#### Migrate the existing single-file HTML5 Canvas shooter game (index.html) to a structured Phaser 3 application. The migration will improve rendering performance via WebGL/Canvas fallback and organize the code into a modular architecture without altering the gameplay, math, economy, or user experience.

#### User Review Required  
#### IMPORTANT  
####   
#### Coexistence of Phaser Canvas and DOM UI Elements We plan to preserve the existing HTML DOM overlay elements (#hudOverlay, #missileBtn, #dragonBtn, #backBtn) and CSS styles exactly as they are in index.html. We will initialize Phaser to bind to the existing <canvas id="game"></canvas> element. This ensures 100% visual layout parity and avoids breaking absolute positioning.  
####   
#### WARNING  
####   
#### Backup of index.html We will backup the current HTML5 Canvas implementation of the game as index.canvas.html in the root workspace. This will allow running the old version alongside the new Phaser version for easy side-by-side comparison.  
####   
#### Open Questions  
#### IMPORTANT  
####   
#### 1. Audio Playback Strategy In the original game, sound effects are loaded dynamically using standard HTML5 new Audio() and played on-demand. Phaser pre-decodes audio into Web Audio buffers during load. This is significantly more performant on Android/mobile but requires sound unlocking gestures. We will implement Phaser's native Web Audio system as the default but fall back to HTML5 Audio if there are decoding issues. Do you have any preference here?  
####   
#### 2. Spritesheets vs Texture Atlases The codebase loads individual images and runs manual frame grid offsets (e.g., T6.png is a 4x4 grid of 256x240 frames). We plan to keep loading them as spritesheets in Phaser using scene.load.spritesheet with exact frame dimensions, maintaining perfect continuity with the assets. Only the lightning ball will be loaded via Phaser's built-in atlas loader since it already has a lightning ball.json file. Let us know if this is aligned with your expectations.

#### Core Architecture & Bootstrap  
#### [NEW]   
#### main.js  
#### Bootstraps the Phaser Game instance. Configures WebGL rendering with a Canvas fallback, binds to the existing #game canvas, and manages scene registration (BootScene, PreloadScene, MainGameScene, UIOverlayScene).  
####   
#### [NEW]   
#### BootScene.js  
#### Handles the boot loading state. Preloads minimal assets (like the loading title or progress bar graphics if any) and immediately transitions to PreloadScene.  
####   
#### [NEW]   
#### PreloadScene.js  
#### Handles loading of all game assets (spritesheets, images, audio, JSON) via AssetManager. It will run the 5-second intro animation sequence (the flying starfield and intro title fade) exactly as it was coded in the original loop. Once the intro timer (5000ms) completes and assets are fully loaded, it transitions to MainGameScene.  
####   
#### [NEW]   
#### MainGameScene.js  
#### The main controller scene that ties together all managers and drives the core game loop. It handles frame timing and directs the updates for gameplay, economy calculations, and collision resolution.  
####   
#### [NEW]   
#### UIOverlayScene.js  
#### Sub-scene running in parallel to MainGameScene that coordinates with DOM UI overlays (e.g. updating balance displays, auto-aim buttons, indicators) and draws custom text/popups in Phaser (like the rising payout values) above the canvas layer.  
####   
#### Systems Managers  
#### [NEW]   
#### AssetManager.js  
#### Wraps Phaser's loader. Declares asset paths, frames, and configurations for all sprites sheets, static images, audio assets, and the lightning ball JSON atlas.  
####   
#### [NEW]   
#### AnimationManager.js  
#### Registers Phaser animations (e.g. cannon barrel rotation, electric ball animation, explosion sheets, boss passes) to the global Animation cache and provides clean API helpers to play them on Phaser sprites.  
####   
#### [NEW]   
#### AudioManager.js  
#### Integrates sound events. Manages play, stop, and volume controls for background music (bgMusic) and sound effects (bullet fire, missile fire, dragon fire). Includes safety wrappers for user interaction unlocks.  
####   
#### [NEW]   
#### InputManager.js  
#### Translates canvas pointer clicks, mouse movement, and touch gestures into aiming coordinates. Directs firing triggers (AUTO, NUKE, DRAGON) to the main scene, updating target positions and active systems.  
####   
#### [NEW]   
#### EntityManager.js  
#### Consolidates entity lifecycle and updates. Manages arrays/pools of:  
####   
#### Player cannon states  
#### Active bullets (movement, border bounces)  
#### Enemies (movement, elite mechanics, custom pathing, boss transitions)  
#### Missiles (nuke targets, homing T2 missiles)  
#### Visual effects (particles, lightning beams, smoke, spark trails)  
#### Collision resolution (circle-to-circle physics intersection checks matching original logic exactly)  
#### killEnemy(...) payout computations, title reveals, and special death sequences (D1 thunder, D2 explosions, etc.)
